# Roadmap

Item IDs are permanent: `P<phase>-<nn>`. Never renumber; append new items at the end of their phase.
`[ ]` open · `[~]` in progress (who holds it, since when, and what is left) · `[x]` done · `[-]` dropped (say why,
and the decision). An item held `[~]` by someone else is theirs until they or a maintainer release it.

A finished item says what was done, the decision if any, the evidence (the test, or the measurement), and the date.
A new item says where it came from (a test run, a real user, a maintainer) and the date. Keep an item's history in it:
"tried X, measured Y, then did Z" is how the next session avoids trying X again. Bugs are items too, filed under
the phase they belong to.

All items below were proposed by the agent and approved by the maintainer on 2026-11-03 unless they say otherwise.
Phases are ordered by dependency; sizes are rough (S under a day, M a few days, L about a week or more).

## Phase 1: The book format

Goal: Scribe can create a valid, empty book and read and edit its package document without rewriting it.

- [x] P1-01 `src/xml-ast.js`: a non-destructive, well-formed XML parser with byte ranges and a splicer, no DOCTYPE or external entities. Done when round-trip and splice tests pass on OPF, nav, and XHTML samples. Size L. Done 2026-11-03 (D-011): offsets are string indices ("byte ranges" in practice means character ranges); `parse()` reports every error with code and position and returns a best-effort tree; namespaces resolved; the DOCTYPE is kept but never processed, with internal entity names noted and never expanded; limits on depth (256), size (16 Mi characters), attributes (1024), and errors (100); generic splices `applyEdits`, `setAttr`, `removeAttr`, `setText`, `insert` (indents like its neighbours, keeps the file's line ends, re-parses to refuse breaking markup), `remove` (takes the whole line when the node is alone on it). Rules re-read from XML 1.0 (Fifth Edition), Namespaces in XML 1.0 (Third Edition), and EPUB 3.3 §3.9 on w3.org, which showed that internal entity declarations are allowed. Evidence: 13 tests in `test/xml-ast.test.js` on four fixtures in `test/fixtures/xml/` (every file rebuilds exactly from its ranges; each splice changes only its range and leaves the file well-formed; 29 malformed inputs give the expected error codes; namespace and security cases), `npm test` 106/106; Python's expat agreed on all 45 well-formedness verdicts, by hand; a 1.3 Mi-character chapter parsed in 82 ms (Node 22, Linux). New landmarks and page-list navs are hidden and go after the last nav. Where EPUBCheck 5.4.0 is stricter than §7, Scribe follows EPUBCheck: text inside nav links, a heading in other navs, links reached only through a fallback, and internal links in other navs. A toc link with no href is a warning. Rules re-read from EPUB 3.3 §7 on w3.org. Found while testing: a new nav or sibling entry took prefixes declared on its neighbour, which it cannot see; fixed. Evidence: 10 tests in `test/nav.test.js` and an EPUBCheck test of a five-step edited nav with no messages; `npm test` 144/144 (140 without EPUBCheck); five deliberate bugs each failed a test; EPUBCheck agreed on 43 of 64 books the tests read, by hand, and the other 21 differ only through stand-in content (see TESTING).
- [x] P1-06 XHTML well-formedness check, entity handling (HTML named entities are not XML), and a pasted-HTML to XHTML normaliser. Size M. Done 2026-11-04 (D-017): `src/xhtml.js` (`Xhtml`). `check(text, { path })` reports XML errors, HTML 4 entities as their own fixable problem (the other checks still run), UTF-8 encoding, DOCTYPE external identifiers (§3.9, Appendix B), the `html`/`head`/`title`/`body` shape, XInclude, `epub:type` on metadata content (§6.1.3.1), and `<base>` and `<rp>` warnings (§6.1.4.3). `fixEntities(text)` returns splices that write the character, or `&#N;` for invisible ones, and skips comments, CDATA, processing instructions, the DOCTYPE, and names the file declares; it works on files that are not well-formed. `normalize(node)` takes the browser's own parse of pasted HTML (`fromHtml` wraps `DOMParser`) and writes an XHTML fragment that keeps meaning and drops presentation: styles, classes, scripts, event handlers, unsafe URLs, Word and Google Docs markup. Bold and italic styles become `<b>` and `<i>`. Images are kept and listed. Rules re-read from EPUB 3.3 §3.9, §6.1, and Appendix B on w3.org. Where EPUBCheck 5.4.0 differs, Scribe follows it (D-016's rule): UTF-8 only (HTM-058), an empty title is an error, and a missing title and a non-`html` DOCTYPE name are warnings. Evidence: 8 tests in `test/xhtml.test.js` and an EPUBCheck test of a chapter with fixed entities and a normalised paste, with no messages; `npm test` 153/153 (148 without EPUBCheck); six deliberate bugs each failed a test; EPUBCheck agreed on 25 of 26 documents the tests check, by hand (the other has a stand-in image); Word-, Docs-, and web-style pastes written for the purpose went through Chromium's DOMParser in the browser pane, and all three gave well-formed XHTML. Not covered: Word's hand-made lists stay paragraphs rather than becoming `<ol>`, inline SVG and MathML in pastes are dropped, and the app does not call any of it yet (`P2-01`, `P2-06`).
